- 每次只做清单中的一项；完成后启动本地预览，交用户检查后再推进。

- 不编造 Tomeisle Bay 的介绍或图片，不添加未确认成员和游戏官网地址。
- 不复制 Capybara Games 的商标、插画、文案或页面源代码；只参考清晰的信息节奏和作品展示方式。
- 保留现有 Astro + TypeScript，无为视觉效果额外引入框架或组件库。
- 视觉稿与实现每次对照桌面、窄屏、键盘焦点和 `prefers-reduced-motion`。

## 第 3 项：吉祥物互动呈现（已验收）

**目标**：让访客能看出吉祥物可以互动；点击与键盘操作都能触发动作，焦点明显但不遮挡形象，并完整尊重减少动态效果偏好。

**现状调用链**：`.studio__mascot-button` 的点击事件调用 `playMascotReaction()`，按 `walk → surprised → celebrate` 轮换 `data-action` 和反馈文案；`studio.css` 根据动作切换六帧精灵图，计时器结束后恢复 idle。

**本项改法**：

1. 在按钮旁增加简短可见提示，并通过 `aria-describedby` 让辅助技术用户知道如何操作。
2. 走路状态下让按钮在吉祥物舞台内短距离移动，同时继续播放现有走路帧；其他两个动作保留当前表情反馈。
3. 对减少动态效果偏好明确关闭角色与按钮位移动画，但仍显示对应的静止姿势与反馈。
4. 键盘焦点沿吉祥物图像轮廓强调，避免方形焦点框罩住透明精灵画布。

**预期触点**：

- `src/components/StudioSection.astro`：保留动作循环与台词，补充可见操作提示及其辅助技术关联。
- `src/styles/studio.css`：实现舞台内行走位移、提示样式和轮廓焦点反馈。
- `src/styles/responsive.css`：控制手机上的提示间距，并在减少动态效果时静态呈现各动作帧。

**单步验收**：鼠标、Enter 和空格触发动作；反馈在短暂显示后复位；提示与吉祥物在手机端不重叠；减少动态效果时动画关闭且表情姿势仍可见；构建通过。
